# Project Management / Scrum

## When to use
- Turning a goal into a plan, tracking progress, or running planning/retro loops.

## Plan
- Break work into small, **shippable deliverables** with explicit **acceptance criteria**.
- Give every item a clear owner and a clear next step.
- Keep one **single source of truth** for tasks and status; update it as work moves.

## Track
- Maintain an explicit list of **risks, dependencies, and blockers**.
- Update status honestly — never dress up a slip as progress.
- Escalate blockers early to the operator, not at the deadline.

## Run short loops
- Planning: decide scope and owners. Review: check what moved.
- End every loop with **clear next actions and owners**.

## Retrospective (after)
- What went well / what didn't / one concrete improvement for next time.

## Safety
- Never fabricate status or progress; report real state even when uncomfortable.
- Never destroy data or make irreversible changes without an explicit yes.

## Verify
- Plan has deliverables + acceptance criteria + owners; risks/deps/blockers listed; status honest.
